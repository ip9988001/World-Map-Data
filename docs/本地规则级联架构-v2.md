# 本地规则级联架构 v2 —— 下载一次，规则随便换

> 用户 2026-10-11 拍板，**取代 v1 的「多引擎下载」方案**（v1 文档保留，见文末对照）：
>
> *「造引擎其实不好。我们应该搞本地解析清洗规则：下载还是只要一个主流的引擎下载即可，
> 下载的时候不要挑数据、不要按规则下载，无规则全量下载。数据到了本地，就用不同的解析规则、
> 清洗规则来处理：第一个规则洗完不对，原始数据**不要删不要扔**，交给第二个规则；
> 还不行，第三个上；再不行你亲自抽查本地几百条看什么情况；本地全量数据你亲自看了
> 还确定不了原因，再回源取样核查。这样就不用下了又删、删了又下。」*

---

## 0. 为什么这版更好（写清楚，免得以后又走回头路）

| | v1 引擎方案 | **v2 规则方案** |
|---|---|---|
| 「多试一把」的成本 | 一次全量下载（MB~GB 流量、被源站限速、可能被 ban） | 几秒 CPU（本地文件已在盘上） |
| 原始数据 | 探针产物丢弃，换来换去 | **不可变资产**，永不删除，可无限重跑 |
| 新规则能否改进存量 | 不能（要回源重下） | **能**：19.7M 存量的原始档可直接重洗 |
| 结论 | 为了省钱拼命「拦在下载前」，本末倒置 | 放心多试几把规则，因为试错不再花钱 |

唯一保留 v1 的部分：**取数协议**。ArcGIS REST / Socrata 这类源，服务端单次最多吐 1000–2000 条，
「全量」本身必须按它的分页协议翻页拿完 —— 这不是挑数据，仍是全量拉取；
**「换下载方式」只在下载残缺/失败/被截断时发生，绝不因解析失败而重下。**

## 1. 三层结构

```
bronze：raw_archive/<state>/<sid>/
            manifest.json      协议 / URL / 字节 / sha256 / 页数 / done / 错误
            payload/           原始字节，永不改动（zip 保持 zip 不解包）
   ↓ 本地摊平 flatten.py（零网络，形态随便多写）
silver：parsed/<state>/<sid>/<rule>@v<n>.ndjson
            每套规则一个产物；不合格 → 只删这套产物，bronze 一个字不动
   ↓ 全规则皆败
分诊：out/triage/分诊-<sid>.json + 报告.md
            先本地抽查 → 本地定不了才回源取样
```

---

## 2. 下载层（`collectors/fetch_raw.py`）

一条主路：**无规则、全量、原样落盘**。不判形态、不挑字段、不解析。

取数协议三选一（`pick_protocol`，只决定「怎么把全量拿完」）：

| 协议 | 触发条件 | 落盘 |
|---|---|---|
| `direct` | 直链文件（.csv/.zip/.geojson/.kml… 或 `accessType=DOWNLOAD`） | `payload/<原文件名>` |
| `arcgis_paged` | `/MapServer/`、`/FeatureServer/` | `payload/features.ndjson`（键集分页全量） |
| `socrata_paged` | `/resource/`、`/api/views/`（且不是直链） | `payload/records.ndjson`（$limit/$offset 翻页） |

- 已有且 `done=true` 的归档**直接用**，不重下；`--force-fetch` 才重抓。
- 每个源一份 `manifest.json`，含 sha256 与 done，中断也留痕（续采锚点）。
- 优先级坑（已踩）：`/api/views/<id>/rows.csv?accessType=DOWNLOAD` 是**直链 CSV**，
  早先按路径含 `/api/views/` 判成分页 API → 抓回空档。现在先判直链，再判分页。

---

## 3. 摊平层（`collectors/flatten.py`，纯本地）

把原始档摊成「字段行」流，支持 ndjson / csv,tsv,txt(BOM/分号/latin-1) / json,geojson /
kml,kmz,xml / zip 递归 / shp(可选依赖)。每条带 `_file` 溯源；读不出的文件产出
`_read_error` 标记行，不炸整批。**这一层失败成本≈0，所以形态可以随便多写。**

---

## 4. 规则架（`collectors/rules/`）—— 规则只增不改

```python
class Rule:
    name, version          # 规则名带版本，账本按此记账；语义变更 = 新规则名
    static_score(row, meta)   # 该不该先出场
    clean(row, ctx) -> (record|None, reason)
    self_test()            # 跑批前全规则自检，不过的不出场
```

现有三套：

| 规则 | 干什么 | 依据 |
|---|---|---|
| `mapping@v1` | **原来的流程**：按源总表的 number/street/city_f/region/postcode 映射 | 存量 19.7M 条一直用它 |
| `field_guess@v1` | 不看映射，靠字段名（多语言关键词）+ 值形态自己猜；猜不到就老实说 `guess_no_columns` | 映射写错/为空/字段没登记 |
| `concat_addr@v1` | 只有一整列「完整地址」→ 拆成 号 + 街（+ 尾部市/州/ZIP、Apt 单元号） | 只给 FULLADDR 的市政源 |

两种跑法：

- **级联**（默认）：按分排序逐套跑，洗出合格数据就收工，不合格只删这套产物。
- **成绩单对比**（`--compare`）：每套规则各跑一遍全量原始档，出量化成绩单，
  按洗出条数排序 —— 这就是「第一套洗完是废数据 → 交给第二套」的量化版。
  本地跑不花钱，所以规则之间不必无条件串行，可以先比成绩。

闸门（与 v1 同一套判据）：合规 ≥ 5 条且合规/原始 ≥ 30%；小源（≤10 行）≥80% 也放行。

## 5. 分诊顺序**反过来**：先本地，后回源（`local_cascade.diagnose`）

1. **本地抽查原始档前几百行**（零成本）——绝大多数情况在这里就能定案；
2. 本地压根没有地址字段（addr_hint 低）→ `NOT_ADDRESS`：源不适用，拉黑；
3. 本地有地址字段但规则都不认 → `RULE_GAP`：造新规则，本地样本直接当造规则的依据；
4. 本地档为空/读不出 → **这时才回源**取样核查：
   - 源也空/4xx/上游 Invalid URL → `SOURCE_BROKEN`，拉黑
   - 源里有数据但本地档空 → `DOWNLOAD_DEFECT`：**下载环节缺陷 → 补采，不换规则**

账本：`data/源黑名单.csv`（30 天后复检）／`data/引擎路由表.csv`（源 → 规则 wins/losses，下次直接用成功的规则）。

## 6. 2026-10-11 实测证据

| 源 | 结果 |
|---|---|
| `us/ca/san_francisco` | 原始档直链 **126.19MB 抓一次**（sha256 落账）→ `mapping@v1` 洗出 **19,998/20,000 = 100%** |
| `us/ms/lauderdale` | 原始档 arcgis_paged 1.01MB → **同档三套规则成绩单**：mapping 353/720 (49.0%)、field_guess 353/720 (49.0%)、**concat_addr 401/720 (55.7%)** ← 第二套规则真的救回 48 条 |
| vs v1 引擎方案 | 同一源在 v1 下是「探针 PASS 55/120」，靠一次额外下载换来的；v2 用同一份本地原始档把三套规则都比完了，**零下载** |

`lauderdale` 的 367 条 `no_number` 正是「映射拿不到号」那批：`concat_addr` 从完整地址列里把它拆出来了。
