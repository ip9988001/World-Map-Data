## 四、数据质量分层（重要发现）

同被 OpenAddresses 标为 `addresses` 图层，实际质量差异极大：

| 源 | 类型 | 保留率 |
|---|---|---|
| `us/co/douglas` | 门牌点 | **100%** |
| `us/oh/statewide`（layer 1）| 门牌点 | **100%** |
| `us/oh/statewide`（layer 2）| 门牌点 | 98.8% |

被丢弃的记录**绝大多数是"没有门牌号"的地块**（如 `SitusStreetName = "ADDRESS ASSIGNED"` 的占位记录）。
**丢弃是铁律的正确执行，不是 bug。**

## 七、本期修复的坑

1. **OpenAddresses `conform` 是「拼接语义」**，不是"取第一个非空"。
   按错语义实现会把街道名取成 `S`（方向前缀）这种垃圾值。
2. **`conform` 还有「函数式」形态**：
   `{"function":"prefixed_number","field":"SitusAddress1"}`（从整串地址里解析门牌号）。
   不支持 → 整个源 0 条（`us/il/edgar` 实测由 0% → 50.4%）。
3. **方向前缀不能被粘进门牌号**：`222 E MADISON ST` 曾产出 `222E`，已修。
4. 新增 `mapping_sanity()`：检出映射里引用但数据中不存在的字段（过期定义预警）。
