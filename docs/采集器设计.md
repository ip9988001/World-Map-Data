# 采集器设计

## 目标
把「源总表」里 1,933 条数据源，用**统一的、礼貌的**方式采下来，清洗成同一套结构。

## 模块

| 文件 | 职责 |
|---|---|
| `collectors/politeness.py` | **采集铁律的代码实现**：每主机最小间隔、并发上限、指数退避、请求日志、`safe_page_size()` |
| `collectors/arcgis.py` | ArcGIS FeatureServer 适配器（覆盖 83%）：读元数据 → 取 `maxRecordCount` → 分页 0.9 → NDJSON |
| `collectors/filedl.py` | 文件下载适配器（zip / CSV / SHP / GDB） |
| `collectors/normalize.py` | 字段映射 + 地址标准化（USPS 缩写字典）+ **无门牌号即丢弃** |
| `collectors/merge.py` | 多源并集合并、主键去重、来源保留（`sources` 数组） |
| `collectors/pilot.py` | 一期样跑入口（CLI） |

## 铁律在代码里的落点

1. **官方上限 × 0.9**
   `arcgis.safe_page_size()`：服务端 `maxRecordCount=1000` → 每页请求 900；`=2000` → 1800。
2. **不施压**
   `Politeness` 强制每主机最小间隔（默认 0.8s）+ 全局并发上限（默认 2）+ 指数退避（2^n，封顶 30s）+ 抖动。
3. **绝不编造**
   `normalize.to_record()` 里：门牌号或街道名为空 → 返回 `None` → 整条丢弃。**没有任何补全分支。**
4. **可追溯**
   请求日志 JSONL（URL / 状态 / 字节 / 耗时 / 重试次数）；每条记录带 `source`，合并后保留 `sources` 数组。

## 关键坑（已踩）

**OpenAddresses 的 `conform` 是「拼接语义」，不是「取第一个非空」。**

```
number = ['STRUCTNO','STRUCTSU']                → 820 + A  = "820A"
street = ['PREDIR','STREETNAME','STREETTYPE']   → S MAIN ST
```

若按「取第一个非空」实现，街道名会变成 `S` 这种垃圾值。已在 `normalize.join_values()` 修正。

## 数据质量分层（实测发现）

源与源的数据质量差异很大，同一个 `addresses` 图层天然分两类：

- **门牌点数据**：几乎 100% 合规（如 `us/or/lake` → 保留率 100%）
- **地块/宗地数据（parcel）**：大量记录没有门牌号，被铁律正常丢弃（如 `us/co/phillips` → 保留率 43%）

**丢弃是正确的**，不是 bug。后续应给源打质量标签，用于估算每个源的实际产出量。
