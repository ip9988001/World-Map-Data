# 多引擎级联架构 v1 —— 一把刀只切一种肉

> 起因（用户原话的工程化）：*「割皮一把刀，割肉另外一把，剔骨又是一把，剁骨又是一把，
> 你不可能一把刀搞定所有的猪肉。遇到切不动的源，就把结果扔掉、换下一把刀；
> 全换完还不行，你自己上手看：是肉有问题（源坏）→ 不管它；是我们没带这把刀 → 再搞一个引擎。
> 不能老是去改一个引擎。」*
>
> 本文是这条原则的落地规格。**核心红线：引擎只增不改；切不动就换刀，绝不回头磨同一把刀。**

---

## 1. 为什么不是「一个引擎 + 一堆 if」

旧实现（`lane.py`）里是硬编码二分支：`channel == ARCGIS` → ArcGIS，否则 → 文件下载。
`normalize.py` 则试图用一套通用映射 spec 通吃所有源的字段规则。
两者都在做同一件事：**用一把刀去适配形态各异的数据源**，结果就是每遇到新形态就要回去改那把刀，
改到后来没人敢动（改一处、崩一片）。

新架构把职责切成三层，每层互不污染：

| 层 | 职责 | 归属 |
|---|---|---|
| 取数 + 摊平 | 「怎么把这坨东西变成字段行」 | **引擎（刀）**，一个形态一把 |
| 字段 → 门牌点记录 | 号/街/市/州/ZIP 的规范化与闸门 | `normalize.py`（全局唯一，所有刀共用） |
| 质量判定 | 这批数据够不够格入库 | 质检闸门 `gate_eval` |

## 2. 刀具架（引擎注册表）

```
collectors/engines/
  base.py        Engine 基类 + 下载前侦察(preflight) + 打分/排序
  __init__.py    注册表 ENGINES + 出场顺序 order_engines / order_by_sniff + 全刀自检
  arcgis_rest.py 刀A：ArcGIS REST 图层（MapServer/FeatureServer，键集分页）
  delimited.py   刀B：分隔符文本（CSV/TSV/TXT/ZIP/SHP）
  json_api.py    刀C：JSON / GeoJSON / Socrata SODA / 通用 JSON API
  kml_xml.py     刀D：KML/KMZ/GML/一般 XML
```

新增一把刀 = **新文件 + 注册表加一行**。老刀永不删除（保留对照与回滚）。
引擎逻辑语义变更必须新开名字（`foo@v2`），因为路由账本是按引擎名记账的。

### 每把刀必须实现

```python
static_score(row)            # 看源总表行打分（零成本）
sniff_score(ct, head)        # 看响应头 + 前 4KB 打分（极廉价）—— 用于下载前拦截
fetch(pol, ctx, budget, probe)   # 取数，落盘成 RawBundle
rows(bundle)                 # 摊平成 dict 流
self_test()                  # 跑批前自检，不过就不出场
probe_reusable = True/False  # 探针产物能否直接复用于全量（省一次重复下载）
```

## 3. 级联流程（一个源）

```
① 下载前侦察 preflight(url)
     一次 Range 请求 → 拿 状态码 / Content-Type / 真实体积 / 前 4KB
     ├─ 网络不通 → TRANSIENT，直接返回（不算判决）
     ├─ 体积 > 200MB 且无刀嗅探分 ≥ 0.90 → 判「形态缺口」，**一个字节都不下载**
     └─ 否则 → 按 sniff 分数排刀：认得的排前，完全不认识的直接不开场
② 逐刀探针（小样 ≤200 条 / ≤25s）
     ├─ 取到数据 → 质检闸门
     └─ 取不到 → 记录判决(SOURCE_BROKEN / NOT_MY_MEAT / FETCH_FAIL) → 换下一把刀
③ 质检闸门 gate_eval（量化）
     合规/原始 ≥ 30% 且合规 ≥ 5 条 → 通过（小源 ≤10 条且 ≥80% 也放行）
     不通过 → **探针产物当场删除**（`_discard`），换下一把刀
④ 探针通过的刀跑全量 → 落 normalized ndjson（每条带 `_engine` 溯源）
⑤ 全刀皆败 → 交分诊（triage.py）
```

**为什么先探针后全量**（本架构相对「字面执行」的关键加固）：
「引擎1下全量→扔掉→引擎2下全量」会让同一份大文件被下载最多次数 = 刀数。
改为小样筛选后，只有胜出的那把刀跑全量，流量从 O(刀数 × 体积) 降到 O(小样 + 体积)。

## 4. 全败分诊（人只看这一份队列，只做两种判决）

`python -m collectors.triage --from-state out/casc/state.json`

| 判决 | 判据 | 处置 |
|---|---|---|
| `SOURCE_BROKEN` | 404/410/401/403、空响应、错误页、上游自报 Invalid URL、空图层 | 拉黑，30 天后自动复检一次 |
| `NOT_ADDRESS` | 能取到数据，但原始字段没有任何门牌点味（addr_hint < 0.34） | 它本来就不是门牌点源 → 拉黑（标注原因） |
| `ENGINE_GAP` | 能取到数据 / 侦察判定有数据，但没有一把刀能摊平或映射 | **造新刀**，产出 `out/triage/待造刀-*.json` |
| `TRANSIENT` | 全是超时/连接错误 | 不判决，下次重试 |

**独立复核（本架构的第二条关键设计）**：拉黑一个源代价不可逆，所以分诊**不信引擎自述**——
`evidence_probe(url)` 自己再抓一次原始响应，只要响应里有数据（json/csv/zip/xml 且 >0 字节），
就不准判源坏，`apply_evidence()` 会把判决强制改判为 `ENGINE_GAP`。

产出物：
- `data/源黑名单.csv`（含 kind/reason/evidence/首见时间/复检日期/命中次数）
- `data/引擎路由表.csv`（源 → 引擎 wins/losses/last_ok）→ 下次该源直接首选成功的刀，跳过全部试错
- `out/triage/待造刀-<源>.json`（失败链 + 独立证据 + 原始字段键名）
- `out/triage/报告.md`（按判决分组的汇总）

## 5. 2026-10-11 实跑证据（架构不是纸上的）

| 源 | 结果 | 说明 |
|---|---|---|
| `us/ms/lauderdale` | ✓ 刀=`arcgis_rest` 合规 55/120 | 侦察认定 FeatureServer 形态，第一把刀即中 |
| `us/ca/san_francisco` | ✓ 刀=`delimited` 合规 120/120 = 100% | 直链 CSV，最便宜的刀排前面 |
| `us/ak/statewide` | `SOURCE_BROKEN` | 上游自报 `{"error":{"code":400,"message":"Invalid URL"}}`，服务已下线 |
| `us/pr/statewide` | `SOURCE_BROKEN` | `data.pr.gov/api/views/h9md-ic24` 现在 404，源总表 URL 过期 |
| `us/az/statewide` | `ENGINE_GAP` | ArcGIS 数据包 `.gdb.zip`，**254MB**；侦察直接拦下，0 下载，出待造刀单 |

**`us/az/statewide` 是本架构的价值实证**：加侦察之前，四把刀各下载 254MB 后齐声说「不认识」，
白烧 ~1GB 流量；加侦察之后，一个字节没下，直接出「待造刀」结论，并附独立证据
（HTTP 200 / application/zip / 有数据 → 是我们的刀不够，不许拉黑）。

## 6. 已知待办

1. **待造刀（等真源积累后再造，不预先造无人用的刀）**
   - `arcgis_item_gdb`：ArcGIS Item 数据包（.gdb.zip）→ 流式选择性解包 + fgdb 读取（pyogrio 可选）
   - `html_table`：网页表格源
   - `odata`：$skip/$top 分页的 OData 端点
2. **接进 lane.py**：`lane.run_lane` 的硬编码二分支改为调用 `run_source()`（同一把刀架，两条路径合一）
3. **黑名单复检任务**：到 `retest_after` 的源自动重跑一次侦察（`kind=ENGINE_GAP` 的除外，它等造刀）
4. **`normalize.py` 的映射 spec** 仍是一套通用规则 —— 它现在只负责「字段语义」，形态差异已由刀吸收，
   风险面比之前小得多；后续若仍出现系统性映射错误，同理可拆「映射器」为多把，而不改原有映射器

## 7. 命令速查

```bash
# 单源试跑（探针）：看哪把刀能切
python -m collectors.cascade --source us/ms/lauderdale --probe-n 120

# 单源全量
python -m collectors.cascade --source us/ms/lauderdale --full

# 批试探针（按 channel 轮抽 N 个源）
python -m collectors.cascade --sample 10 --probe-n 120 --out out/casc

# 单刀验证（只让一把刀出场）
python -m collectors.cascade --source us/az/statewide --only delimited

# 分诊（现场跑 + 独立复核 + 写账本）
python -m collectors.triage --source us/az/statewide
python -m collectors.triage --from-state out/casc/state.json
```
