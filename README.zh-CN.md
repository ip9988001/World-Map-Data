# World-map-data

**世界地图公开数据库 · 归集整理总仓库**

> 一个经过归集、标准化、可追溯的**全球公开地址数据公地**。
> [English →](README.md)

---

## 我们为什么要做这件事

地址数据是**数字时代的公共基础设施**。但在今天，绝大多数地方的地址数据是：

- **碎片化的** —— 散落在成千上万个县、市、省、国家门户之间；
- **不统一的** —— 格式各异、字段各异、编码各异、粒度各异；
- **昂贵的** —— 商业地址库价格高昂，个人与小型团队根本拿不到；
- **难以审计的** —— 你几乎无法知道一条记录究竟从哪里来。

与此同时，**开发者、测试工程师、研究人员和学生，长期需要"可用的测试地址"**。当没有可信的开放测试数据时，最省事的做法就变成了**直接采样真实住户的地址** —— 这会造成真实个人信息的泄露，伤害真实的家庭。

**本项目存在的意义，就是终结这种两难。**

我们把**公开可获取**的地址数据收集起来、统一标准化、完整保留来源与授权，再以开放、机器可读的形式发布 —— 让任何人都可以在**不触碰任何一个真实家庭私人信息**的前提下，基于真实的地址结构去开发软件、编写测试、开展研究。

**免费、开放、可署名、可审计 —— 这才是它存在的理由。**

## 这是什么

- **一份数据公地**：从公开、可追溯的源头聚合，统一到同一套数据结构。
- **一条保留来源的流水线**：每一条记录都保留其来源标识与授权信息。
- **真实的结构，而非凭空的编造**：数据取自真实存在的地址记录。

## 这不是什么

- **不是个人数据**。不含姓名、电话、身份、个人属性等信息。
- **不是欺诈工具**。不得用于冒用身份、信贷欺诈、绕过监管或平台核验。
- **不是商业校验服务**。需要权威校验请使用各国官方邮政机构。

---

## 两条铁律

### 一、数据铁律 —— 绝不编造

- **只收录真实存在的地址记录。**
- 数据源若只提供**区间**（形如 `100–198`），我们**只取该侧两端**，中间号一律丢弃，**绝不推算合成**。
- **没有门牌号的地址，整条不做。**
- **宁可数据少，不可数据假。**

### 二、采集铁律 —— 绝不给公共服务添负担

- **严格遵守对方公布的限额。** 官方接口单次上限 1000 条，我们就只取 **900 条**。
- 内置速率限制、并发上限与失败退避。**宁可爬得慢，也不触发反爬、也不给公共端点施压。**
- **全程记录请求日志**，并把每个数据源的授权与署名要求随数据一并保存。

## 数据源

所有上游数据源均为**公开且免费**的。我们不绕过任何认证、不突破任何付费墙。

| 层级 | 来源 | 说明 |
|---|---|---|
| 聚合层 | **OpenAddresses** | 源定义库公开在 GitHub |
| 聚合层 | **OpenStreetMap** | Geofabrik 分州提取 / Overpass API |
| 检索层 | **ArcGIS Online / Hub** | 县市级要素服务的统一检索入口 |
| 检索层 | **Socrata** | 市政开放数据的统一检索入口 |
| 国家级（美） | **US Census TIGER/Line** | 覆盖 100%，公有领域 |
| 州/县/市 | 各地政府开放数据门户 | 逐源适配 |
| 国际 | 日本 · 法国 · 澳洲 · 荷兰 · 英国 · 韩国 · 台湾 · 香港 · 新加坡 · 新西兰 | 官方公开地址库 |

每个源的授权与署名要求，记录在源总表的 `license` 字段中。

## 授权与署名

各上游数据源授权不同，主要分三类：

- **公有领域**（如 US Census TIGER/Line）—— 无限制；
- **CC-BY / 需署名**（如 GeoNames、多数地方政府数据）；
- **ODbL**（OpenStreetMap）—— 署名，且**衍生数据库需同许可**。

我们逐源保留这些信息。**若你分发衍生数据，你需要继承上游许可所规定的义务。**

## 使用规范

**允许用途**：软件开发、自动化测试、质量保障、教学、研究、地理信息工程、隐私保护实践。

**明确禁止**：身份欺诈、信贷或福利欺诈、冒用他人身份、绕过监管或平台风控，以及任何会对真实个人或组织造成伤害的用途。

本仓库不含任何真实个人数据，任何贡献者也不得引入任何真实个人数据。
